T19 — Resolve direct PHP import/namespace bindings and lexically bound function references into `bindings` rows. No receiver-based rules (T20/T21), no CLI output changes beyond the `bindings` count in `index --json`.

Design so T20 and T21 can add rules in parallel:
1. Create `crates/rivet-index/src/resolve/mod.rs` with a `Resolver` that loads, for one snapshot, all symbols (id, qualified_name, lookup_name, kind, file) and exposes `resolve_all(store) -> Vec<BindingRow { use_id, target_id, resolution }>`. It iterates uses in `(file bytes, start_byte, end_byte, ref_kind)` order and applies an ordered list of rule functions `fn(&RuleCtx, &UseRow, &ScopeFacts) -> Option<(SymbolId, Resolution)>`; the FIRST rule returning a single candidate wins; a rule that finds more than one candidate returns None and records nothing (conflicting hints never bind). Rules live one per file under `resolve/rules/`: T19 adds `imports.rs` and `functions.rs`; T20 will add `receivers.rs`; T21 will add `new_expr.rs`. 2. `imports.rs` (`exact`): a `Type`/`Import`/static-call receiver spelling that matches an import alias visible in the use's scope chain (walk `scope_key` → `parent_scope_key`) binds to the symbol whose `qualified_name` equals the import's `target_qualified` (PHP case-insensitive comparison for classes), if exactly one such symbol exists in the index. A use spelled with a fully qualified name (`\App\Services\SurveyService`) binds directly when exactly one symbol matches. An alias whose target is not indexed yields no binding (the use stays unresolved, never name_match-bound in the table).
3. `functions.rs` (`exact`): an unqualified function `Call` use inside namespace `N` binds to `N\name` if that function symbol exists in the index and no closer lexical declaration shadows it; otherwise, per PHP fallback rules, to the global `name` if that exists; if both exist, the namespaced one wins (that is PHP's rule, not ambiguity). A `use function` import alias resolves via imports.rs first. Method and static calls are NOT handled here.
4. Namespace-relative class names: an unqualified class spelling `Foo` used in namespace `N` with no matching import binds to `N\Foo` if exactly one such symbol exists (`exact`, because PHP resolves this lexically). Put this in `imports.rs` as the last step of that rule.
