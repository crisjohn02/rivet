## Decisions (orchestrator, final)

1. **Receiver class.** A TypeScript member use with a hint gets a receiver class only as follows:
   - **`this`** (`UseHint::This`): the named class that encloses the use (the class T43 recorded
     the hint for; arrow functions inside members are transparent, as T43 already decided).
   - **Typed** (`parameter`, `variable`, `property`): the type name in the annotation.
   - **`new`** (`NewExpr`): the class named after `new` at the `const`'s initializer.

   For typed and `new` hints, the class name is resolved **in the scope where the annotation or
   `new` expression is written, not the use's scope**, through the same T44 lexical rules
   (same-file declarations with shadowing and type/value spaces, direct relative imports, and
   namespace-import members such as `ns.Foo`). A type-position name (annotation) needs a
   type-space declaration; a `new` target needs a value-space one. The two scopes can differ:
   `const a: Foo` at module level used inside `namespace N { class Foo {} a.m() }` must resolve
   `Foo` at module level, never to `N.Foo`. The hint therefore needs to carry enough to find its
   annotation scope (for example the annotation's type-use span or its scope key); pick the shape,
   bump the fact-schema, and say what you chose. A generic type parameter that shadows the name
   (`function f<Foo>(x: Foo)`, `class Box<Foo> { f: Foo }`) leaves the receiver without a class.

   The resolved declaration must be exactly one **class or interface** symbol. A type alias, enum,
   namespace, function, an unresolved or ambiguous name (including declaration merging, e.g.
   `class X` plus `interface X`), a package or path-alias import, or a re-export gives no receiver
   class.
2. **Member lookup.** The receiver class must itself declare **exactly one** member with the use's
   spelling (methods, accessors, fields, constructor parameter properties, ES private names with
   their `#`, interface method and property signatures). Overload signatures already fold into one
   symbol.
   - **No inheritance traversal**: a member declared only on a base class stays unresolved (gold
     case i, `this.log`). Never walk `extends`/`implements`.
   - **Static versus instance.** `this` inside a static member, static block, or static field
     initializer may bind only static members; every other receiver (instance `this`, typed, `new`)
     may bind only instance members. A class may declare a static and an instance member of the
     same name; the side that matches decides. If a class declares a static `m` and inherits an
     instance `m`, an instance receiver's `m` must stay unresolved, never bind the static one.
     `UseHint::This` currently has no static marker and stored symbols have no static flag: record
     both (on the hint, and as a stored fact the resolver can read without reparsing, in the
     symbol row or the class's scope facts, your choice) and bump the fact-schema. If staticness is
     unknown, do not bind.
   - A getter/setter pair sharing a name is two candidates → unresolved (TypeScript uses record no
     read/write distinction). Say so in the README.
   - An interface receiver binds to the interface's own member declaration; it never maps to an
     implementing class (§11.4).
3. **Tier.** Every binding T45 makes is `scoped`. Never `exact`, and never upgraded by uniqueness.
   A use that already binds through a T44 rule (a namespace-import member) is unaffected.
4. **What stays unresolved.** Untyped receivers (gold case g), `let`/`var` bound by `new`, union,
   array, function and structural annotations, anything with no hint, calls on a class name
   (`SurveyService.create()`, `Status.Active`; parked as a follow-up, record it in the report),
   computed members (`obj[name]()`), and chained receivers the hint does not cover
   (`this.a.b.m()` when `b` has no hint).
5. **No exclusion change.** TypeScript stays out of evidence-based exclusion (§11.5). Do not write
   `receiver_classes` rows for TypeScript uses; the `!is_php` gate in `resolve/mod.rs` stays for
   that table. Reference mode for a TypeScript target still lists every unresolved same-name use as
   `name_match`.
6. **Query integration without language branches.** `refs`, `symbol` (whose call lists default to
   `scoped`), and `context` must show the new scoped bindings through the existing generic code.
   Add no `language == "typescript"` branch outside `rivet-languages` and the resolver's rule
   table. If you find a place in the query path that needs one, stop and report it.
7. **Nothing else changes.** PHP extraction and resolution are unchanged; PHP output is
   byte-identical apart from the snapshot digest. Bump `RESOLVER_FINGERPRINT` (TypeScript rules
   changed, PHP unchanged; say so in the history note) and the fact-schema/extractor fingerprint.

## Tests (adversarial required)

- **Gold:** all 8 T45 entries: `this.service.launch()` (property), `created.launch()` (`new`),
  `svc.launch()` and `svc?.launch()` (parameter), `annotated.launch()` (variable),
  `this.launch()` in `relaunch` (this), `x.launch()` unresolved, `this.log` unresolved (inherited).
- **Same-name members:** `this.launch()` in `ReportService` binds `ReportService.launch`, never
  `SurveyService.launch`.
- **Annotation scope:** the `namespace N { class Foo {} }` case above; a generic type parameter
  shadowing the class name, on a function and on a class.
- **Imports:** a receiver typed through a direct relative import, an aliased import, a default
  import of a class, and `ns.Foo` through a namespace import all bind; one typed through a package
  import, a re-export, or an ambiguous module (`./pick`) does not.
- **Not a class:** a receiver typed as a type alias, an enum, or a merged `class X` + `interface X`
  stays unresolved. An interface receiver binds to the interface member.
- **Static:** `this.m()` in a static method binds a static `m`; in an instance method it binds an
  instance `m`; a class with both a static and an instance `m` binds each side correctly; a static
  `m` plus an inherited instance `m` leaves an instance call unresolved.
- **Accessors:** `this.label` with a getter/setter pair stays unresolved.
- **Hint gaps:** `let x = new C(); x.m()`, `this.m()` inside a nested `function`, an
  object-literal method, and an anonymous class, a union-typed parameter, and `obj[name]()` all
  stay unresolved.
- **Missing member:** a typed receiver whose class declares no such member stays unresolved.
- **Query path:** `rivet refs` for `src/services/survey.ts#SurveyService.launch` lists the five
  scoped uses as `scoped` and the untyped `x.launch()` as `name_match`; `--min-resolution scoped`
  drops the latter; `rivet symbol` shows `relaunch`/`ReportService` methods among callers of
  `SurveyService.launch`; `rivet context` for `ReportService.runTyped` shows its scoped callee.
  Check JSON and human output.
- **Freshness:** renaming `SurveyService.launch` unbinds `report.ts`'s uses on the next refresh
  with `report.ts` untouched; restoring it rebinds them.
- **Determinism:** identical output across `--force` and file orders.
