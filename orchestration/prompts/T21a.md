T21a — Make the `new`-receiver reassignment test cover every way a PHP variable can be rebound.

The defect, reproduced against main. T21's rule refuses to bind when a receiver variable is assigned more than once in its scope, counting assignments from `ScopeFacts::new_bindings`. The walker fills that list only from `bind_variable`, which is reached only from a simple `$x = ...` assignment expression. Every other rebinding form is invisible, so the variable still looks singly assigned and the call binds to the class of the stale `new`. All of these currently bind `Alpha::go` as `scoped` after `$s = new Alpha();`, and all but the last are plainly wrong:

- `foreach ($xs as $s) {}`
- `[$a, $s] = [1, 2];` and the `list($a, $s) = ...` spelling
- `$s = &$o;`
- `catch (\Throwable $s) {}`
- `$f = function () use (&$s) { $s = mk(); }; $f();`
- `$s ??= mk();` and the other compound assignments (`.=`, `+=`, ...)

A plain `$s = mk();` control case is correctly unbound, which proves the resolver logic is sound and the gap is in what the extractor records.

Requirements:

1. Prefer inverting the test over enumerating forms. Enumerating PHP's rebinding syntax is unbounded and will rot. The safer shape: bind only when the walker can account for every mention of the receiver variable in the scope, and treat any occurrence in a position the walker does not positively classify as a read as a reason to record nothing. If you instead enumerate, you must state why the inverted form was not workable and list exactly which constructs you covered.

2. Whatever the mechanism, the default on an unrecognised construct is NO binding. A variable whose history the extractor cannot fully account for records nothing. Never guess, and never bind at `exact`.

3. Keep the existing correct behavior. The safe single-assignment case must still bind `scoped`, and the four T21 conditions must still hold. `crates/rivet-cli/tests/bindings.rs` asserts an exact binding count on the authored fixture; if your change alters it, say so explicitly with the before and after numbers and justify each difference. I expect the authored fixture to be unaffected, so a change there is a signal to re-examine your work.

4. Tests. One unit test per rebinding form listed above, in the extractor or the rule as fits. Each must assert no binding. Add the plain-reassignment control case asserting it is still unbound, and a safe single-assignment case asserting it still binds `scoped`. Add an integration test in `crates/rivet-cli/tests/bindings.rs` covering at least `foreach`, destructuring, and `catch` end to end through the binary.

5. Be honest about `??=`. On a non-null value it does not fire, so the current binding may be right by accident rather than by rule. Say which side you land on and why. If you suppress it, say that you are trading a correct binding for a rule you can defend.
