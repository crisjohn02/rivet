AF2 — Make declaration lookup respect the kind of use, and fold case only as PHP does.

The defects, each reproduced by the orchestrator on the current binary, plus one confirmed during the AF1 review:

1. Finding 4. A fully qualified call binds to a class. In `rules/imports.rs`, a fully qualified spelling goes to `RuleCtx::unique_resolved`, which accepts a symbol of any kind. `class Maker {} \Maker();` binds the call `exact` to the class. Kind-specific lookups already exist beside it: `unique_function`, `unique_class_like`, and `unique_const`. Route a fully qualified use to the one matching its use kind. A call binds only to a function, a constant read only to a constant; a type use is already handled through the class path above it.
2. Finding 5. Member lookup ignores the use kind. `RuleCtx::unique_member(class_id, spelling)` accepts a method, property or constant, and `member_name_matches` strips the leading `$` from properties. So `class C { public $items; public function run(){ $this->items(); } }` binds the method CALL `scoped` to the PROPERTY `C::$items`, although no method `items` exists. The reverse also happens: a property read can bind to a same-name method. Make `unique_member` take the use kind, so a method call matches only a method, an instance or static property access only a property, and a class-constant access only a constant. It has three callers: `rules/receivers.rs`, and two in `rules/new_expr.rs`. One of those resolves a callee for by-reference parameter detection, which is a method call.
3. Finding 10. Case folding is Unicode, but PHP folds identifiers by ASCII only. The qualified-name index in `resolve/mod.rs` uses `to_lowercase`, so `class Ä {}` with `new ä()` binds `exact`, while PHP treats them as distinct classes.

4. Confirmed during the AF1 review, previously an unverified audit suspicion. When a namespaced function's own file failed to parse, an unqualified call in that namespace falls back to the global function and binds `exact`, although the real namespaced function exists and simply was not indexed. The fallback in `rules/functions.rs` is only honest when no unindexed file could declare the namespaced function. Suppress the global fallback when any file of the same language that should have been indexed was not, meaning a PHP file skipped for a parse error, resource limit, size, or encoding. Do NOT key this on the snapshot's overall `coverage.complete` flag: it is already false for any repository containing a non-PHP file such as a README, so keying on it would disable the fallback everywhere. Say exactly which skip reasons you counted and why. A namespaced function that IS indexed still wins over the global one, and with every PHP file indexed the fallback must behave exactly as before.
