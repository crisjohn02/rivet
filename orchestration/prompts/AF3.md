AF3 — Give typed receivers the conservatism `new` receivers already have, and close the remaining rebinding forms.

Background. Across T21, T21a and T21b, the `new`-receiver rule in `new_expr.rs` learned to refuse a binding when the variable is reassigned, rebound by any syntactic form, passed to a by-reference parameter, or used in a scope containing an unanalysable construct. The typed-receiver rule in `receivers.rs` learned none of it. These defects were reproduced by the orchestrator on the current binary; each gives a wrong `scoped` binding:

1. Finding 6. `function f(A $x){ takes_ref($x); $x->m(); }` with `takes_ref(&$v){ $v = new B(); }` binds `A::m`. The audit also reports a reference alias, `extract($vars)`, `preg_match('/a/', 'a', $x)`, and `for (...) { $x->m(); $x = new B(); }`, which reassigns after the use inside a loop.
2. Finding 7. `function g(A|B $x){ $x->m(); }` binds `B::m`. `first_named_type` in `uses.rs` pops a stack and so returns the LAST named type. The same helper feeds property types.
3. Finding 8, `new` receivers. A reference alias, `$x = new A(); $y = &$x; $y = new B(); $x->m();`, binds `A::m`, because the right-hand side of a reference assignment is visited as a plain read. A constructor by-reference argument, `new Holder($x)` with `__construct(&$v)`, is missed because `visit_object_creation` records no call arguments. A file-scope variable rebound by a called function, `$x = new A(); reset_it(); $x->m();` with `reset_it(){ global $x; $x = new B(); }`, is missed.
4. Finding 9. The by-reference parameter check in `new_expr.rs` re-parses the stored signature text and anchors on the first occurrence of the word `function`, so `#[Deprecated("use function other")] #[Pure(1)] function rebind(&$v)` misreads the parameter list.

Read this before designing the typed-receiver fix, because it decides what is honest. PHP checks a PARAMETER's declared type only when the function is called. Inside the body, `$x = new B();` is legal even when `$x` is declared `A`, so a parameter's declared type says nothing once the variable is rebound. PHP checks a typed PROPERTY on every assignment, so an `A`-typed property can only ever hold an `A` or a subclass, and the `scoped` tier already accounts for subclass dispatch. Therefore:
- A typed PARAMETER receiver, including a promoted constructor parameter used as the local variable inside the constructor, must be suppressed by every condition that suppresses a `new` receiver: any rebinding of the variable anywhere in the scope, an unanalysable scope, and a by-reference call argument adjudicated as in T21b.
- A typed PROPERTY receiver needs no rebinding check. Do not suppress it for reassignment. It still needs the union-type fix.
Suppressing both uniformly throws away honest bindings; treating both as properties keeps dishonest ones. State the rule you implemented for each.

Requirements:
