## Decisions (orchestrator, final)

1. **Export facts.** Record what each module exports:
   - `export` on a declaration;
   - `export default <named declaration>`;
   - `export default <identifier>` naming a local declaration;
   - `export { a }` and `export { a as b }`, including `export { a as default }`.

   Re-exports (`export { x } from`, `export *`) are recorded but **not followed**.
   `export default <expression>` and anonymous defaults identify no declaration. Bump the
   fact-schema for this.
2. **Module lookup** follows ADDING-A-LANGUAGE's ordered candidate set exactly: the exact
   supported path, `.ts`, `.tsx`, `.d.ts`, `/index.ts`, `/index.tsx`, `/index.d.ts`.
   - Only relative specifiers (`./`, `../`) are looked up.
   - The result needs a **unique** valid candidate across the whole set. If two exist (the
     fixture's `./pick` has both `pick.ts` and `pick/index.ts`), the import is unresolved; never
     guess.
   - Candidates are matched against **indexed paths, byte-exact**, never the filesystem. On
     case-insensitive filesystems, `./Util` must not match `util.ts`.
   - A candidate that is unindexed (a parse failure or an unsupported extension) is not valid.
3. **Binding rules:**
   - **Named and aliased imports.** `import { a }` and `import { a as b }` from a resolved module
     bind the import use, and every unshadowed use of the local name, to the declaration the
     module exports as `a` (following `export { x as a }` renames within that module) → `exact`.
   - **`import type`** binds the same way → `exact`. This corrects the T41 gold, which marked it
     unresolved; fix that gold entry and say so.
   - **Default imports** bind to the module's default export when it identifies one explicit local
     declaration → `exact`. Otherwise unresolved.
   - **Namespace imports.** `import * as ns`, then `ns.member`, binds `member` to the declaration
     the module exports as `member` → `exact`.
     - This is a lexical module-qualified name, not member access on an object, so the §11.4
       receiver-evidence clause does not apply.
     - Update §11.4's wording and ADDING-A-LANGUAGE to say this explicitly.
     - `ns.member.deeper` binds only `member`.
   - **Same-file lexical bindings.** A use whose name resolves lexically, with shadowing accounted
     for, to exactly one declaration in its own file binds to it → `exact`. This matches §11.3's
     `exact` example: "a lexically bound named function with shadowing accounted for".
     - Respect T43's value and type spaces. A type-position use can only bind to a type-space
       declaration (class, interface, enum, type alias, namespace). A value use can only bind to a
       value-space declaration (function, class, enum, const, namespace).
     - When merging leaves more than one candidate in the needed space, as with `interface X`
       twice, the use is unresolved (§11.4: reject multiple candidates).
   - **Stays unresolved:**
     - uses through re-exports, `export *`, path aliases (`@/x`), packages, `require`, an import
       of a name the module does not export, and an import from an unresolved or ambiguous module;
     - everything on a receiver other than a namespace import (`this.x`, `obj.m()`). T45 owns
       receivers.
4. **Nothing else changes.**
   - PHP resolution is unchanged; PHP output is identical apart from the digest.
   - TypeScript exclusion stays off.
   - Bump `RESOLVER_FINGERPRINT` with a history note that says which languages' rules changed.

## Tests (adversarial required)

- **Gold:** all T44 gold entries, including the corrected `import type` binding.
- **Ambiguous modules:** `./pick` stays unresolved, and so does a module that has both `x.ts` and
  `x.d.ts`.
- **Byte-exact paths:** a case-mismatched specifier is unresolved on this Mac.
- **Unindexed modules:** importing from the broken file, a `.js` file or a `.mts` file is
  unresolved.
- **Renames:** `export { a as b }` followed by `import { b }` binds to `a`'s declaration.
- **Missing exports:** a non-exported name, and a name the module does not declare, are unresolved.
- **Defaults:**
  - `export default function named()` binds;
  - `export default someConst` binds to `someConst`;
  - `export default () => {}` is unresolved.
- **Namespace imports:** `ns.member()` and a type-position `ns.Member` both bind; `ns.missing` is
  unresolved.
- **Shadowing:** a local `double` hides the imported `double` (the gold's `shadowed`).
- **Value and type spaces:** `interface X` plus `const X` means a type use binds to the interface
  and a value use to the const. A double `interface X` means a type use is unresolved.
- **Circular imports:** `a.ts` and `b.ts` importing each other resolve without looping.
- **Freshness:** removing an export in `util.ts` unbinds dependents on the next refresh, with no
  other file touched.
- **Determinism:** identical output across `--force` and file orders.
