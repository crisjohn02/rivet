## Decisions (orchestrator, final)

1. **The project.** Hono, `https://github.com/honojs/hono`, tag `v4.13.9`, commit
   `7c3b0df96dbf3e767968ff5afe4c0d999257b8ee`, MIT. At that tag it tracks about 329 `.ts`,
   32 `.tsx` and 1 `.d.ts` files, uses relative imports, and has classes read through typed
   receivers (`c: Context`), so it exercises T44 and T45. Verify these counts yourself and record
   the real ones.
2. **No vendored source.** Do not commit Hono's code. Add:
   - a manifest `tests/real/manifest.toml` (name, URL, tag, commit, licence, file counts, the
     rivet commit it was measured with), with a `schema_version`;
   - `tests/real/fetch.sh`, which clones or fetches into `$RIVET_REAL_DIR` (default
     `target/real/`, already ignored by git; check), checks out the pinned commit detached, and
     verifies `git rev-parse HEAD`. Idempotent; refuses to run over a dirty checkout.
3. **Contract checks** live in `tests/real/check_real.py` (standard library only, Python 3.9+),
   driving a built `rivet` binary passed by `--rivet` (default `target/release/rivet`). Each check
   prints PASS or FAIL with a reason, and the script exits nonzero on any FAIL. It works on a
   **copy** of the fetched project in a temporary directory, never on the fetched checkout. The
   checks, for both languages:
   - **Determinism.** Two clean indexes of the same tree give byte-identical `index --json`
     output apart from timing fields, and byte-identical query output.
   - **Full versus incremental.** From a clean index, apply a scripted, seeded sequence of edits and
     refresh after each: modify a function body, rename a method its callers use, remove an export
     that other files import, add a new file that imports an existing one, delete a file, rename a
     file, and introduce then fix a syntax error. After each step, the incremental store must answer
     exactly as a `--force` rebuild of the same tree does: byte-identical JSON for `symbol`, `refs`
     (both modes) and `context` over a deterministic sample of symbols (all symbols in edited files
     and their dependents, plus a seeded sample of at least 200 others), and identical `coverage`.
     If the snapshot digest differs between the two, that is a FAIL; report it, do not mask it.
   - **Coverage.** Record files seen, indexed, and skipped by reason, symbols, uses, and bindings by
     tier and language. Parse failures are listed by path.
   - **Two languages in one repository.** Copy the authored PHP fixture and the authored TypeScript
     fixture into one tree. PHP queries must be byte-identical to a PHP-only tree's apart from the
     snapshot digest, and likewise TypeScript to a TypeScript-only tree's. No use in one language
     binds to, or is listed in reference mode for, a declaration in the other.
   - **Budget honesty.** For a seeded sample of `context` queries on Hono at two budgets, the
     rendered output respects `--budget` as OUTPUT-CONTRACT defines it.
   PHP has no public real project in this repo, so its real-project coverage stays with the private
   benchmark corpus; say so in the docs rather than inventing one.
4. **Honesty audit (by reading source).** On Hono, draw a seeded sample of 40 `exact` and 40
   `scoped` bindings and check each against the source by hand: is the target the declaration the
   use refers to? Record every wrong one with its file and line and why. Then sample 40 unresolved
   member calls and classify why each stays unresolved (untyped receiver, inherited member, chained
   property, class-name receiver, qualified type annotation, re-export, package import, path alias,
   other). The T45 review found two conservative gaps worth counting under "qualified type
   annotation": a receiver typed `ns.Inner.Foo` (deeper than one namespace-import member) and one
   typed `Local.Foo` through a same-file `namespace Local`, both unresolved. This is the
   evidence for the known limitations. Do not change any resolver rule in this task. If a binding is
   wrong, report it as a defect with a minimal repro in the authored-fixture style; the orchestrator
   decides the fix.
5. **Known limitations.** Write `tests/real/RESULTS.md` (counts, check results, audit tables,
   timings from the indicative protocol in `benchmark/corpus.toml`'s header) and add a
   "Known limitations on real code" section to the TypeScript README, with the measured frequency of
   each unresolved category. Keep ADDING-A-LANGUAGE's support boundary as it is unless a measured
   fact contradicts it; report any contradiction.
6. **Nothing in the binary changes.** No Rust changes except tests, and not even those unless a
   check needs a hook it cannot get from the CLI; if so, stop and report. Fingerprints are
   unchanged.
