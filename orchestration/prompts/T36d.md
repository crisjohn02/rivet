## Why

The pilot benchmark showed `refs` on a base class omits every subclass,
because `extends` and `implements` clauses are never visited. A follow-up task
(LR2) will also need each class's supertypes to decide whether a method call on
a receiver of known class could reach a given method. This task records both.

## Build

1. **Base-clause uses.** In `visit_class`, visit the `base_clause` (`extends`)
   and `class_interface_clause` (`implements`), and an interface's `extends`
   list, for named *and* anonymous classes, enums (`implements`), and interfaces.
   Each named type there becomes one `RefKind::Type` use pushed exactly the way
   `record_scope_class` pushes a class name, so it resolves through the existing
   import/namespace rules and gets the same honest tier those rules give (no new
   tier logic). The use's containing symbol is the class being declared (for an
   anonymous class, whatever `containing_symbol` already gives its members'
   context; do not create a symbol for the anonymous class).

2. **`$expr::$prop` scopes.** In `visit_scoped_property` (and the scoped call and
   class-constant paths, if they share the gap), when the scope is an arbitrary
   expression (for example `$obj::$prop`, `$this->m()::X`, `(expr)::$p`), walk
   that expression with `visit` so the uses inside it are recorded. A plain
   name scope keeps its current handling. Do not record the expression itself
   as a type use.

3. **Hierarchy facts.** Persist, for every named class-like symbol (class,
   interface, trait-free: traits are out of scope here, enum), its declared
   supertypes as written plus the facts needed to resolve them (the file's
   namespace and imports are already stored per scope; reuse them rather than
   duplicating). Expose from `rivet-index` a function along the lines of

   ```rust
   /// Declared direct supertypes of `class`, each resolved to indexed class-like
   /// symbols when the import/namespace rules bind it, otherwise the qualified
   /// name only. Sorted, deduplicated, deterministic.
   pub fn direct_supertypes(snapshot, class: SymbolId) -> Vec<Supertype>
   /// Transitive closure over indexed supertypes, cycle-safe, sorted.
   pub fn ancestors(snapshot, class: SymbolId) -> Vec<Supertype>
   ```

   (names and exact signatures are yours; match the surrounding code). An
   unresolved supertype (a vendor class) is kept as a qualified name with
   `resolved: None`, never guessed. Cycles (`A extends B`, `B extends A`, which
   PHP rejects but the parser accepts) must terminate.

4. **Fingerprints.** Bump `EXTRACTOR_FINGERPRINT` (fact schema changes) and, if
   any resolution rule changes, `RESOLVER_FINGERPRINT`. Bump the store schema
   version if the schema changes, following the existing migration/rebuild rule.

## Tests (write these; adversarial ones are required)

- `refs` on a fixture base class lists `class Sub extends Base` with the tier
  the import rules give: imported-by-`use` case, same-namespace case, fully
  qualified `\Ns\Base` case, and an unimported name that does not resolve
  (stays unresolved/name_match per current rules, never upgraded).
- `implements A, B` records two uses; interface `extends I1, I2` records two.
- Anonymous class `new class extends Base implements I {}` records both uses
  and still creates no symbol for the anonymous class (regression of the
  earlier anonymous-class leak).
- Enum `implements`.
- `$obj::$prop`, `$obj::CONST`, `$obj::method()`, `$this->f()::$p`: the uses inside
  the scope expression are recorded; no bogus type use for the expression.
- Hierarchy API: direct and transitive supertypes, a vendor (unindexed)
  ancestor kept as a name, a cycle terminating, deterministic order across two
  refreshes with different file walk orders if the test harness allows it.
- Byte-identical output across two refreshes.

Add fixture files under `tests/fixtures/php/` only if the existing fixture

base-clause or scope-expression uses; list every golden you changed and why in
