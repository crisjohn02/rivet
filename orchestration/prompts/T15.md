T15 — Changed-content refresh on the query path, with removals, and no reparsing of equal content.

Context: T10–T12 built `index::run`, which currently re-reads and re-extracts EVERY enabled-language file on every invocation. T15 makes that incremental and makes every query command go through it.

Requirements:
0. Architecture fix first: ARCHITECTURE assigns the Tree-sitter driver to `rivet-parser`, but T10–T12 left PHP parsing inside `crates/rivet-cli/src/index.rs` and `rivet-parser` is a stub. Move the parse-and-extract step into `rivet-parser` as `pub fn parse_file(language: LanguageId, bytes: &[u8]) -> ExtractedFile` (creates the Tree-sitter parser for the grammar, parses, dispatches to the language adapter's `extract`, and applies the node cap). `rivet-cli` must no longer depend on `tree-sitter` directly or call `rivet_languages::php::extract`; it calls `rivet_parser::parse_file`. Keep the grammar smoke tests where they are.

1. Factor the refresh out of `index.rs` into `crates/rivet-cli/src/refresh.rs` with `pub fn refresh(root, config, store, mode: RefreshMode) -> Result<RefreshOutcome, CliError>` where `RefreshMode::Content` is the only mode implemented in T15 (T16 adds Metadata and Cached). `RefreshOutcome` carries the T10 `Report` data (coverage, diagnostics, counts, digest) so `index` and the query commands share it. `index::run` becomes a thin wrapper that calls `refresh` and formats.
2. Incremental behavior inside the single publish transaction:
   a. Walk eligible files (T06). For each enabled-language file read bytes and hash (T07). Compare the hash to the stored `files.content_hash`. If equal AND stored `parse_status` is `ok` AND the extractor fingerprint in meta equals the current one: do NOT reparse; keep the stored symbols; still update mtime/size. Otherwise reparse and replace that file's symbols (T12 path).
   b. Files present in the store but absent from the walk (deleted, renamed away, or newly excluded) are removed with their symbols (cascade). A renamed file therefore appears as one deletion plus one new file.
   c. A file that was `ok` and now fails to parse (`parse_error` or `resource_limit`) loses ALL its previous symbols and gets the diagnostic; a file that was failing and now parses gains symbols.
   d. A same-size edit with the original mtime restored MUST be detected in content mode (this is the whole point of content hashing): the test must edit a byte, `utime` the file back to its original mtime, and assert the new symbol span/hash is returned.
   e. `updated`/`unchanged` counts in the report follow T09 semantics (content_hash, parse_status, language), so an untouched file is `unchanged` even though its row was rewritten.
3. Every implemented query command (`symbol` for now; `refs`/`context` later reuse the same entry point) calls `refresh` first, then reads from the committed snapshot. There must be exactly one code path that performs a refresh.
4. Extractor fingerprint check: if `meta.extractor_fingerprint` differs from `EXTRACTOR_FINGERPRINT`, reparse all enabled-language files regardless of hash equality (grammar changed). Store the new fingerprint via the existing publish path.
5. Integration tests in `crates/rivet-cli/tests/refresh.rs` on a temp copy of the authored fixture with a `.git` dir, using the built binary:

   - deletion: delete `boot.php`; `rivet symbol App\Boot\launch --json` exits 4.
   - rename: `git mv`-free rename of `ReportService.php` to `Reports.php`; the old id exits 4, the new id (`Reports.php#App\Reporting\ReportService::launch`) succeeds.
   - valid-to-malformed: overwrite `boot.php` with the malformed snippet; `rivet symbol App\Boot\launch --json` exits 4 AND `rivet index --json` shows `skipped.parse_error == 1` with a diagnostic naming `boot.php`; restore the file and the symbol is found again.
   - same-size + restored mtime: change one byte inside a method body without changing length (e.g. `'survey'` → `'survex'`), set mtime back with `filetime`-free approach (`std::fs::File::set_modified` on stable Rust; if unavailable on the pinned toolchain, use the `touch -d` command via `std::process::Command`), then `rivet symbol ... --source --json` returns the NEW byte and a NEW `content_hash`.
   - no-reparse proof: add a counter or a `RIVET_DEBUG_REPARSED` env var (only read when `cfg!(debug_assertions)`) that makes the binary append the list of reparsed paths to a file named by the variable; run `index` twice with no edits and assert the second run reparsed nothing, then edit one file and assert exactly that file was reparsed.
