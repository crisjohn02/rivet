## Target selection (neutral, seeded, logged; do this for all 20 now)

Targets must be chosen by a recorded procedure, not by taste. This limits the risk that an author
who knows rivet's strengths picks favourable cases.

1. **Universe.** List every first-party method and function declared in fluent's application PHP
   code. Exclude `vendor/`, generated code, migrations, config and tests; test files are only gold
   for the `tests` category. Build the list with a script, from `rg` or from the frozen rivet's
   symbol table in your scratch copy. Declaration listing is neutral parsing. Sort by
   `file` then `qualified name` in bytes, and save it as `heldout/selection/universe.txt`.
2. **Order.** Shuffle it with `random.Random(20260927)`: one shuffle of the sorted list, saved as
   `heldout/selection/order.txt`.
3. **Assignment.** Walk the shuffled order once. For each candidate, check it against the
   categories in the fixed rotation locate, callers, tests, trace, dependencies, skipping any
   category already holding 4 targets. Assign it to the first category whose eligibility it meets.
   If it meets none, skip it.
4. **Logging.** Log every candidate you examined, with its outcome and a reason, in
   `heldout/selection/log.md`: assigned to a category, skipped as ineligible and why, or rejected
   for a recorded reason. The only reasons for rejecting an eligible candidate are:
   - the gold is not verifiable by reading;
   - a second defensible answer can't be ruled out in the prompt;
   - it duplicates an already chosen target's code path.

   Never reject because of how rivet or `rg` would do on it.
5. **Batches.** Stop when every category holds 4. Tasks h01–h10 take the first two targets of each
   category in assignment order, and batch 2 takes the rest. Record the full 20-target assignment in
   `heldout/selection/assignment.md`, so batch 2 cannot re-pick.

Eligibility, decided by reading the code. `rg` and rivet may help you find things, but the decision
comes from the code:

- **locate:**
  - The body is at least 5 lines.
  - The behaviour can be described in domain words, without its name, its class name, or a
    near-synonym of either, and that description identifies exactly one symbol.
- **callers:** 2 to 10 direct first-party call sites. Gold is the set of containing symbols.
- **tests:** reached by 1 to 8 tests, where "reached" follows the pilot's definition in the pilot
  README. The project's tests are PHPUnit, not Pest like the pilot's, so a gold item is the test
  method, `{"file": <test file>, "symbol": "<TestClass>::<testMethod>"}`, compared by the runner's
  normal symbol rules. Say so in the prompt's answer format.
- **trace:**
  - The method is reachable from an entry point (route handler, console command, job `handle`,
    event listener, or scheduled task) through 3 to 6 direct first-party call hops.
  - Gold lists **every** accepted path. Name the start point in the prompt.
- **dependencies:** it directly calls 3 to 10 distinct first-party methods or functions. Gold is
  that set.

## Each task

Write `task.toml`, `prompt.md`, `gold.json` and `notes.md` in the pilot's style:

- **`prompt.md`:**
  - It names no tool, and it is identical for both arms.
  - It ends by requiring a final fenced `json` block, in the check's answer shape.
  - It must state whether direct references or behavioural reach are meant, where that matters.
- **Gold.**
  - Established by reading the code.
  - Cross-checked two independent ways, with `rg` and with the frozen rivet on your scratch copy.
  - Every disagreement is resolved from the code and recorded in `notes.md`.
  - The gold reflects the code, never a tool's output.
- **`notes.md`** also records, **before any run exists**, the expected favour for the task: text
  search, rivet, or neutral, with the reason. This is the same practice as the pilot README.
- **Validation:**
  - Every gold answer passes its check.
  - At least two wrong answers fail: a near miss and an empty answer.
  - Validate through the runner's check module, `run_study.py validate` with a scratch manifest
    that lists h01–h10.
  - Also keep a standalone `heldout/validate.py` self-test in the pilot's style.
