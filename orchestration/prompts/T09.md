T09 — Atomic publication of a file inventory and a deterministic snapshot digest, in `rivet-store`. No parsing, no symbols, no CLI wiring.

Requirements:
1. `Store::publish_inventory(&mut self, input: InventoryInput) -> Result<PublishReport>` where `InventoryInput { fingerprint: Fingerprint, files: Vec<FileRow> }` (FileRow from T08, `source` may be None for skipped files) and `Fingerprint { index_format_version: String, effective_config: String, extractor: String, resolver: String }`. The whole publish runs in ONE `BEGIN IMMEDIATE` transaction: replace the complete `files` inventory (rows not in `input.files` are deleted; present rows are inserted or updated), write the four fingerprint values plus `snapshot_digest` into `meta`, then commit. If any step fails, roll back so the previous complete inventory and meta are untouched (test this by injecting a failure: e.g. pass a duplicate path so the PRIMARY KEY violation fires mid-way, and assert the prior inventory is intact afterwards).
2. `PublishReport { updated: u64, unchanged: u64, deleted: u64, digest: String }` computed per docs/OUTPUT-CONTRACT.md "index --json": `updated` counts rows whose content_hash, parse_status, or language changed or that are new; `unchanged` counts rows present before and after with none of those changed (mtime/size-only changes count as unchanged but their mtime/size are still written); `deleted` counts rows removed. `updated + unchanged == files.len()`.
3. Snapshot digest exactly per ARCHITECTURE: BLAKE3 over a canonical length-prefixed byte sequence of: index format version, effective config fingerprint, extractor and resolver fingerprints, then for each eligible file sorted by path bytes: path, language or empty, content_hash or empty, parse_status. Length-prefix every field with its byte length as an 8-byte little-endian integer so concatenation is unambiguous. Exclude mtime, size, absolute root, row IDs, and wall time. Format `blake3:` + 64 lowercase hex. Provide `pub fn snapshot_digest(fingerprint, sorted_files) -> String` as a pure function and use it inside publish. Add `blake3` to `rivet-store` deps (already pinned in the workspace by T07; reuse that pin).
4. Tests: publishing the same inventory twice yields the same digest and `updated=0, unchanged=n`; publishing in a different input order yields the same digest; changing one file's content_hash changes the digest and gives `updated=1`; changing only mtime gives `unchanged` for that file and the same digest; removing a file gives `deleted=1` and a different digest; changing `effective_config` alone changes the digest; the injected mid-transaction failure leaves the previous inventory and previous digest intact; `list_files` after publish equals the input sorted by path bytes.
