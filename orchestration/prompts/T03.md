T03 — Shared spans, symbol IDs, and resolution enums in `rivet-core`. No database, no parsing, no language logic.

Requirements, all in `crates/rivet-core/src/` (split into modules `span.rs`, `id.rs`, `kinds.rs`, re-exported from lib.rs):

1. `Span { start_byte: u32 or usize, end_byte }` zero-based half-open. Constructor validates `start_byte < end_byte` and returns `Result`. A `LineIndex` built from source bytes that maps a byte offset to one-based `line` and one-based UTF-8 byte `column`, and gives the inclusive `end_line` for a span (the line containing `end_byte - 1`). CRLF is two bytes; do not normalize. Columns are byte columns, not display or UTF-16 columns.
2. `SymbolKind` enum: Class, Function, Method, Interface, Struct, Enum, Module, Property, Const. `Resolution` enum: Exact, Scoped, NameMatch, ordered so `Exact < Scoped < NameMatch` (derive Ord) with a `min_resolution` filter helper. `RefKind` enum: Call, Type, Import, Assignment, Read, Write, Unknown. All three serialize to the snake_case strings in OUTPUT-CONTRACT (`name_match`, etc.) via `as_str()` and parse back via `FromStr`. Do not add serde yet.
3. `SymbolId`: build from `(path, qualified_name, Option<ordinal>)`. Encode literal `%` as `%25` and `#` as `%23` inside the path component and the qualified-name component, then join with `#`; an ordinal is appended as `#N` (one-based). Provide `parse(&str) -> Result<SymbolId>` that splits on unescaped `#`, decodes components, and reads a trailing numeric ordinal, rejecting malformed input (bad escapes, empty components, zero ordinal, more than one trailing ordinal). Round-trip must be lossless. Provide `assign_ordinals` taking a list of `(qualified_name, span, kind)` within one file and returning ordinals only for names that occur more than once, numbered one-based in `(start_byte, end_byte, kind)` order, with every member of a duplicate group numbered including `#1`; unique names get `None`.
