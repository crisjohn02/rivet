## Decisions (orchestrator, final)

Resolve the gold's T43 `[[undecided]]` entries accordingly.

1. **Re-export specifiers.** The local name in a re-export specifier (`export { double } from
   "./util"`) is an `import` use. It stays unresolved, because re-exports are not followed.
2. **JSX attribute names** are not uses.
3. **JSX closing tags.** A closing tag's name (`</Card>`) is not a second use. Only the opening or
   self-closing tag name is a use.
4. **T41 conventions stand:**
   - a capitalized JSX component use is `ref_kind = call`;
   - an identifier before `.` is `unknown`;
   - an import use sits on the local alias.
5. **`import type`** is extracted as an `import` use and import binding like any named import,
   with the `type` flag recorded. T44 resolves it; the T41 prompt was wrong to call it
   unresolved. Leave its gold binding for T44 to correct.

## Build

1. **Uses and scopes.** For both grammar variants, extract the uses ADDING-A-LANGUAGE's TypeScript
   column defines:
   - calls, including `new`;
   - member calls, with receiver text and the receiver hints T45 will need (`this`, a preceding
     `new`, explicit parameter, field or variable annotations);
   - type-position uses;
   - reads and writes;
   - JSX component names and expression containers;
   - template-literal interpolation (literal text excluded);
   - top-level uses.

   Nearest named container, or null inside anonymous containers, as T42 defined symbols. Record the
   lexical scope and shadowing facts T44 needs to decide that a local of the same name hides an
   import.
2. **Imports.** Record import bindings and their import uses:
   - named, default, aliased and namespace imports;
   - `import type`;
   - re-export specifiers, marked as re-exports;
   - `export *`, which creates no binding;
   - path-alias and package specifiers, recorded as written for T44 to leave unresolved.

   `require(...)` is a call use of `require`, not an import.
3. **Turn TypeScript on.**
   - Flip `LanguageId::has_extractor()` to true for TypeScript and TSX.
   - Bump `EXTRACTOR_FINGERPRINT`'s fact-schema, with a history note, so caches that recorded
     `.ts`/`.tsx` as unsupported rebuild. Prove a pre-T43 cache is refreshed correctly.
   - The existing T41/T42 "CLI unchanged" test is replaced by tests of the new behaviour.
4. **No resolution yet.** T44 and T45 add TypeScript binding rules. Until then **every TypeScript
   use must stay unresolved**.
   - Audit the existing (PHP) resolver rules. Make sure none binds a TypeScript use by accident,
     for example a function-name rule, the import rule or the `new` rule. Put the guard where the
     code keeps language dispatch, and document it.
   - Test that after indexing the fixture, no TypeScript use has a binding.
5. **No evidence-based exclusion for TypeScript in v0.1.**
   - LR2's form table in `exclusion.rs` is PHP-shaped. In TypeScript, functions and consts are
     routinely referenced with a qualifier (`Outer.f()`, a namespace import's `util.format()`,
     `Color.Red`), classes are called through `new`, and `typeof x` puts a value in a type
     position. So the PHP table would drop real references.
   - Receiver-class exclusion is unsound under TypeScript's structural typing: a variable typed
     `Foo` may hold any shape-compatible object.
   - Therefore, for a target or use in a TypeScript file, **neither** exclusion rule applies, and
     `by_exclusion` stays 0.
   - Document this in spec §11.5 and ADDING-A-LANGUAGE.
   - Tests: `Outer.f()` against function `Outer.f`, `util.format()` against function `format`, a
     bare read of a top-level `const`, `new Foo()`, and `Color.Red` are all kept in reference mode.
6. **Queries work, honestly.**
   - `symbol`, `refs` and `context` on TypeScript symbols work through the generic path. Every
     TypeScript reference is `name_match` until T44.
   - Lookup is case-sensitive, as T42 set.
   - Mixed PHP and TypeScript repositories work.
   - PHP behaviour and output are unchanged, except for the snapshot digest and fingerprint.
7. **Gold.** Mark T43 done. Its entries are verified by the extractor harness, as T42 did. Also
   check them end to end through the CLI (`rivet index --json` plus a query), or explain why
   not. `check_gold.py` reports truthfully.
8. **Determinism and freshness.**
   - Byte-identical output across `--force` and across file orders.
   - Editing one `.ts` file re-extracts that file only, and an unchanged file's uses are reused.

## Tests (adversarial required)

- **Gold:** every T43 gold entry.
- **Shadowing:** a local `double` shadowing an imported `double` gives distinct scope facts.
- **Anonymous containers:** a use inside an IIFE or callback in an anonymous default export has a
  null container.
- **Excluded text:** JSX text and string attribute values are not uses; `{expr}` inside JSX is.
- **Templates:** `${a}` inside a template literal is a use, and the text around it is not.
- **Optional chaining:** `a?.b()` records the receiver.
- **Type-position uses:** a generic argument (`Box<Config>`) and `typeof x`.
- **Mixed repository:** a PHP class `Foo` and a TypeScript class `Foo` in one repository are
  different symbols. Case-sensitive TypeScript lookup against case-insensitive PHP class lookup is
  documented.
- **Real-shaped TSX:** props destructuring, map callbacks and conditional rendering.
- **Cache upgrade:** a pre-T43 cache refreshes to the new facts.
