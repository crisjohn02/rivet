T37 — Measure the local PHP slice on the pinned corpus, with no model calls and no agent. This is the benchmark's first, free stage. It measures rivet itself.

The corpus is PRIVATE and this repository is PUBLIC. These rules override everything below:
- Run only against the clean copies in /Users/cris/rivet-corpus/, `fluent` as the primary project and `timesheet` as a second, smaller one. NEVER read, index, modify or run anything under /Users/cris/ssr/.
- For any edit, make a scratch copy under /tmp, edit that, and delete it afterwards. Never edit the corpus copies themselves.
- Commit only numbers and code of your own. No source text, no file paths inside the projects, and no class, namespace or qualified names. Query targets may be generic short method names common to Laravel code, such as `handle`, `get` or `save`, and results may be reported only as counts, sizes and times.

Requirements:

1. Measure, with a release build, on each project, and report each as the median plus the minimum and maximum of at least 5 runs:
   a. Cold index, with `.rivet/` deleted first.
   b. A no-change query in content mode, the default, and separately in metadata mode, which trusts size and mtime.
   c. A one-file edit followed by a query.
   d. A common-name `refs` query, for a short name with many declarations and uses. Report its `total` and its `by_resolution` breakdown alongside the time.
   e. A high-fanout query: the symbol or context query with the most candidates you can find, reporting `candidate_limit_reached`.
   f. `context` output size in bytes at several `--tokens` budgets, such as 1,000, 4,000 and 16,000.
   g. Index size on disk, and peak memory, via macOS `/usr/bin/time -l` maximum resident set size, for the cold index and for a query.
2. Separate content hashing from resolution cost, as the T37 row requires. Derive it where you can by difference: a no-change content refresh minus a no-change metadata refresh approximates hashing; a one-file edit minus a no-change refresh approximates reparse plus full re-resolution. If differences are not enough, you may add phase timing gated behind an explicit environment variable that is off by default and writes only to stderr. When unset, output must be byte-identical and stderr must stay empty, since the T36 stream tests assert that. Say which approach you used.
3. The output-format comparison promised in `orchestration/review-notes/output-format.md`. For the same queries, measure bytes for `--json` against the default text form, for `symbol`, `refs` and `context`, and report the envelope share for JSON: total bytes against the source bytes carried. Also report rivet's own `ceil(bytes / 3)` estimate for each, clearly labelled as rivet's estimate and not a real tokenizer's count; a real tokenizer comparison is T47.
4. Record the environment: machine model, CPU, memory, macOS version, `rustc --version`, the rivet commit measured, whether the OS file cache was warm or cold, and the corpus commit SHAs from `benchmark/corpus.toml`.

For the common-name query in 1d, report how many lines `rg -n -w <name>` matches and its time, beside rivet's `total` and time. Spec §11.2 explains why the counts differ: `rg` also matches declarations, comments, strings and unrelated same-name uses. Report counts only, never the matched lines.
