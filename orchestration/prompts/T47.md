## Decisions (orchestrator, final; user-approved 2026-09-24)

1. **Tokenizer source.** Anthropic's token-counting endpoint (`POST /v1/messages/count_tokens`)
   with `model = "claude-opus-5-5"`, the pilot and held-out benchmark model. It runs no model. Use
   the official Python SDK (`anthropic`), `client.messages.count_tokens(model=..., messages=[{"role":
   "user", "content": text}])` → `.input_tokens`, installed into a virtualenv under the worktree's
   ignored `target/` (never globally, never a requirement of the rivet build). Credentials come
   from the environment the user set up (`ANTHROPIC_API_KEY`, or an `ant auth login` profile); if
   none is available, stop immediately and report that, without writing workarounds. Never print,
   log, or write a credential.
2. **Overhead.** A count includes the message wrapper. Measure the wrapper once per run by counting
   a minimal message (for example a single `a`) and a second minimal message, and subtract the
   derived constant from every sample; record the constant and how it was derived. Report both raw
   and wrapper-subtracted numbers.
3. **Samples (public only).** All deterministic, seeded, and listed with sha256 in the results:
   - every file of the authored PHP and TypeScript fixtures;
   - a seeded sample of at least 150 Hono `.ts`/`.tsx` files (pinned by `tests/real/manifest.toml`),
     stratified by size;
   - **Unicode:** fixture files with non-ASCII identifiers or strings, plus synthetic samples built
     from them (CJK, accented Latin, emoji in comments and strings);
   - **minified:** deterministic whitespace- and comment-stripped versions of 30 Hono files made by
     a small documented stripper in the script (labelled synthetic; no third-party minifier);
   - **rendered outputs:** for a seeded sample of at least 60 Hono symbols, the complete stdout of
     `rivet context` (human and `--json`) at `--tokens 1000` and `4000`, and of `rivet symbol` and
     `rivet refs` (human and `--json`). For `context`, record both the full rendered output's tokens
     and the tokens of just its source segments, against the output's own `estimated_tokens`.
4. **Measures.** For each sample: bytes, `ceil(bytes/3)`, actual tokens, the ratio
   actual/estimate, and signed relative error. Report by category (PHP, TS, TSX, Unicode, minified,
   rendered human, rendered JSON) the p5/p25/p50/p75/p95/max ratio, the share of samples where
   actual exceeds the estimate, and, for `context`, how often the real source tokens exceed
   `--tokens` and by how much. For rendered outputs, also report tokens per output byte and the
   metadata overhead (full output tokens minus source-segment tokens).
5. **No behavior change.** This task measures only. Do not change the estimator, its ID, budgets,
   or any Rust code. If the data argues for a different estimator (for example a per-language
   divisor), write it up as a recommendation with its projected error distribution, labelled as
   such; the orchestrator and user decide.
6. **Caching and cost.** The endpoint is free but rate limited: use the SDK's retries, a small
   concurrency (≤4), and cache results by `(model, sha256(text))` in an ignored file under
   `target/` so a re-run makes no repeat calls. Record the number of calls made.
