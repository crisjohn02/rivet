## Why

On Hono (T46), 140 of 1,634 named and default imports (8.6%) use a bare `.` or `..` specifier
(`import { x } from '..'`). The module rule applies only to specifiers starting with `./` or `../`
and rejects a trailing `/`, so they all stay unresolved.

## Decisions (orchestrator, final)

1. **Directory-only specifiers.** TypeScript's own CommonJS-style lookup
   (`normalizePathForCJSResolution`) treats `.` and `..`, and any specifier whose last segment is
   `.` or `..` (`../..`, `./x/..`), as a directory, and a specifier ending in `/` (`./`, `../`,
   `./dir/`) likewise. For all of these, the candidate set is **only** `/index.ts`, `/index.tsx`,
   `/index.d.ts`, in that order, joined to the resolved directory. Never the exact path, `.ts`,
   `.tsx` or `.d.ts`: `..` from `src/a/b.ts` must never name `src.ts`.
2. **Everything else is unchanged.** Specifiers starting with `./` or `../` and not ending as above
   keep the existing ordered set. An empty *interior* segment (`.//x`, `..//x`) still names no
   module. A specifier that leaves the repository (`..` from a top-level file) names none. The
   unique-candidate, byte-exact, indexed-TypeScript-only rules apply unchanged: two index
   candidates (`index.ts` and `index.tsx`) is ambiguous; an unindexed one still counts toward
   ambiguity.
3. **Tier.** Bindings through these modules are `exact` exactly as T44's are; nothing else about
   binding changes.
4. **Fingerprint.** Bump `RESOLVER_FINGERPRINT` to `php-rules-v4;ts-rules-v3` with a history note
   (TypeScript module lookup only; PHP unchanged). No fact-schema change should be needed; if one is,
   stop and report.
5. **Docs.** Update the ADDING-A-LANGUAGE paragraph, the `ts_scopes` module doc, and the TypeScript
   README's known-limitations import table (mark the row as resolved by T44a; do not re-measure
   Hono by hand, but if you run `tests/real/check_real.py --only coverage` record the new
   counts in `tests/real/RESULTS.md` and `manifest.toml` as a dated T44a addendum rather than
   overwriting T46's numbers).

## Tests (adversarial required)

- Unit tests on `lookup_module`: `.` from `src/pick/x.ts` names `src/pick/index.ts`; `..` from
  `src/pick/x.ts` names `src/index.ts`; `../..` from `src/a/b/c.ts` names `src/index.ts`; `./` and
  `../` behave like `.` and `..`; `./dir/` names `src/dir/index.ts`; `./x/..` names the importer's
  own directory index.
- Negative: `..` never names a sibling file `src.ts` or `../x.ts`-style file even when that is the
  only candidate; `..` from a top-level file names nothing; `.//x` names nothing; a directory with
